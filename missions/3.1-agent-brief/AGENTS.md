# Миссия 3.1 · ТЗ агенту

Неделя 2. Работы больше, чем рук. Студент ставит первое ТЗ агенту с границами
и заводит `AGENTS.md` штаба.

## Цель миссии

Студент отличает запрос модели от ТЗ агенту, задаёт границы действий и создаёт
`rok-crisis-room/AGENTS.md`.

## Скрипт

### 1. Чем агент отличается от чата

Скажи: «Первая неделя мы работали как с умным собеседником: спросил — ответил.
Вторая неделя другая: я буду ходить по файлам, считать, писать в штаб,
запускать помощников. Модель + инструменты + цикл "план → действие → проверка →
поправка" — это уже агент. Агенту мало хорошего запроса — ему нужно ТЗ,
потому что он **действует**, а не только говорит.»

Check: «Как думаешь, что добавляется в ТЗ агенту по сравнению с запросом
модели из миссии 1.3?» (границы: что можно и нельзя делать; точки контроля —
где агент останавливается и ждёт человека; критерий готовности результата
действий, а не текста).

### 2. Границы и контроль

Скажи: «Главный вопрос ТЗ — не "что делать", а "чего не делать". Правило штаба:
обратимые действия (прочитать файл, посчитать, создать черновик в
`rok-crisis-room/`) — свободно. Необратимые (написать клиенту, изменить
данные компании, удалить файл) — только с моего "да". Пока агент новый —
стартовый режим: читать всё, писать только в штаб.»

Check: «Расклассифицируй четыре действия: (1) прочитать claims-batch-1.md;
(2) дописать строку в evidence/ledger.md; (3) отправить черновик письма Олегу
из «Зари»; (4) переименовать файл в company/data/.» (1–2 — свободно,
3 — стоп и вопрос человеку, 4 — запрещено: первоисточники неприкосновенны).

### 3. AGENTS.md штаба

Скажи: «Закрепим правила там, где агент их прочитает сам при каждом запуске —
в `AGENTS.md` нашего штаба. Это его "трудовой договор": роль, зоны доступа,
правила работы с доказательствами.»

Action: создай `rok-crisis-room/AGENTS.md`:

```markdown
# Штаб РОК — правила для агента

Ты — аналитический агент антикризисного штаба ООО «РОК».

## Роль
Помогаешь ведущему аналитику готовить доклад к совету директоров:
читаешь данные, считаешь, обновляешь реестр доказательств и черновики.

## Можно без спроса
- Читать `company/**` и `rok-crisis-room/**`
- Создавать и править файлы внутри `rok-crisis-room/`

## Только с разрешения человека
- Любые письма и тексты "от компании" (черновик — можно, отправка — стоп)
- Изменение чего-либо вне `rok-crisis-room/`

## Никогда
- Не менять файлы в `company/` — это первоисточники
- Не придумывать цифры: нет в источнике — пиши "нет данных"
- Не выдавать гипотезы за выводы: помечать статусом

## Реестр доказательств
Каждый факт в докладе должен быть строкой в `evidence/ledger.md`
с источником. Гипотезы живут в `hypotheses.md` со статусами.
```

Check: «Открой файл и проверь: хватит ли этих правил, чтобы я завтра не
"оптимизировал" тебе данные компании?» (студент проверяет покрытие рисков).

### 4. Завершение

Action: допиши в `rok-crisis-room/diary.md`:

```markdown
## День 9 — ТЗ агенту

- Заведён rok-crisis-room/AGENTS.md: роль, границы, точки контроля.
- Правило: обратимое — свободно, необратимое — через человека,
  первоисточники — неприкосновенны.
```

Action: перезапиши `.progress/rok.local` строкой `3.1|<текущая дата ISO>`.

Скажи: «Трудовой договор подписан. Следующий шаг — научить штаб повторять
нашу лучшую рутину без долгих объяснений. Скиллы. Готов?»

## Критерии завершения

- Студент назвал отличия ТЗ агенту от запроса и расклассифицировал действия.
- Создан `rok-crisis-room/AGENTS.md` с границами.
- Дневник дописан, прогресс записан: `3.1|<дата>`.
